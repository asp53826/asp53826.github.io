    how it works

    Proposal acceptance is not commit evidence.

    The minority leader may append locally, but only a current-term entry replicated to a majority can advance the commit index. The console above shows exactly that: isolate the leader, propose, and the new entry sits outlined in amber, appended but never committed, until a heal repairs it away.

    Deterministic transport

    The cluster is an in-process transport that can isolate a node, partition, drop messages, heal and drive logical time. Because delivery is deterministic, every failure replays exactly, without sleeping or hoping a race appears.

    Serializable OCC on MVCC chains

    Each key owns an ordered chain of immutable versions. A transaction commits only if its commit timestamp is later than its read timestamp and every read or written key still has exactly the version it observed. That is stricter than snapshot isolation, so lost updates and read/write anomalies abort.

    An offline linearizability checker

    It partitions a history by key, enforces real-time precedence, explores legal register states with memoization, and returns a witness when one exists. The oracle buttons above run it on a valid overlapping-write history and on a stale read.

    where it stops holding

    A protocol laboratory, not a production database.

    • No network or diskThe throughput excludes sockets, serialization, fsync and scheduler overhead. These are simulator numbers; the useful comparison is 3 nodes against 5.
    • No snapshots or membership changesLog compaction, joint consensus and adding or removing nodes are listed as missing instead of being implied.
    • Single range onlyTransactions are atomic within one replicated range. Cross-range transactions would need a commit protocol this does not implement.
    • Ticks are not time"11 ticks to failover" is deterministic simulator steps. Wall-clock election timing on a real network is a different measurement.
